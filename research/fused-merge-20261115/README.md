基于 `research/minimal-reference-20261114` 的 `fc894fe`。只新增本目录；`demo.rkt`、`pkgs/` 没有改动。方案和讨论见 [#22](https://github.com/NoahStoryM/amb/issues/22#issuecomment-6887431533)。

| `bench.rkt` | 方程与融合版的时间 |

## 对照的是什么

两边用同一个观察器：请求一次；得到 0 再请求；得到 n 记 n 个暂停。**每得到一个逻辑事件**，记下此刻叶子生成器被调用的总次数；最后比较整条「事件 + 次数」序列和完整的调用日志（哪个叶子、第几次、先后次序）。所以比较的是 #22 里说的两个等价：事件相等（含结束），以及强制时刻相同。原始返回值不比较，它们确实不同。

- 叶子的原始结果随机取自答案、`0`、`1–4` 的批量暂停；可以以「一调用就抛异常」或「此后永远返回 0」（第 300 个 0 时抛异常，代替不终止）收尾。两边必须在同一个事件之后、带着相同的日志停住。
- 叶子结束后再被调用就报错，所以「`#f` 之后不调用 next」也在检查之内。
- 表达式是四种策略的随机嵌套，左深为主；`(drop k e)` 表示先取走 k 个逻辑事件，再把剩下的当作操作数（包括停在 level 一轮中间、停在一批暂停中间）。

## 结果

Racket 9.3 CS，`LC_ALL=C.UTF-8`，先删 `compiled`：

```sh
cd research/fused-merge-20261115
rm -rf compiled ../minimal-reference-20261114/compiled
raco test tests.rkt programs.rkt catenable-tests.rkt     # 15 个测试通过，约 10 秒
racket bench.rkt
```

- `tests.rkt`：约 1.4 万个随机表达式，全部一致。
- `programs.rkt`：7000 个随机程序，全部一致。
- 改错测试：对 `merge.rkt` 做了 15 处语义改错（拼接顺序两种策略各一、0 当作结束、0 当作暂停、0 换边、批量 n 多等一轮、批量 n 只算一个（两种策略各一）、已暂停者排到前面、轮末不暂停、还有人等待时就独自继续、答案丢掉等待者、丢掉待办的其余部分、提前调用下一个生成器），每一处都被 `tests.rkt` 发现。另有 2 处「遇到同种记录不展开而是调用它」：结果不变，只是回到平方，`tests.rkt` 的步数测试因此跑不完（240 秒超时），没有别的测试能发现它。

时间（ms，5 次的中位数）：

| | 方程 | 融合 |
|---|--:|--:|
| append，左嵌套 1000 / 2000 / 4000 / 8000 / 16000 | 11 / 41 / 133 / 596 / 2435 | 1 / 2 / 7 / 12 / 27 |
| level，左嵌套 1000 / 2000 / 4000 | 9 / 32 / 130 | 1 / 2 / 5 |
| append，合并了再合并 5000 / 10000 / 20000 | 164 / 688 / 2793 | 0 / 1 / 1 |
| level，合并了再合并 5000 / 10000 / 20000 | 146 / 581 / 2631 | 0 / 1 / 1 |
| append，宽：200000 个备选 | 68 | 84 |
| append，10 皇后 | 176 | 195 |
| append，深：2^18 个叶子 | 274 | 273 |
| level，深：2^14 个叶子，带暂停 | 23 | 29 |

没有嵌套可以压平的程序上，融合版慢一到两成（每次合并多一条记录和一个表节点）。
