# 提交前的观察器计数修正

最初的 C/D drain 用 `(min fuel r)` 截断一个暂停块。默认 fuel 是 `+inf.0`，Racket 的 min 会把被选中的整数 r 转成浮点数，使暂停累计数也变为浮点数。这会把观察器自身的数值转换和装箱混入 C/D 的 CPU 与分配量；A/B 的逐次整数加法没有同样的路径。

发布到 GitHub 前改为 `(if (< fuel r) fuel r)`，保留实际被选操作数的精确性，重新运行全部 13×4 测量并生成表格。run-bench.py 另检查答案和暂停计数必须是 JSON 整数，不能仅靠数值相等放过 1.0 与 1 的区别。

这只修正 benchmark 观察器；A/B/C/D 内核、语义期望和源流事件没有改变。最初下载包中的相关性能数字是修正前结果；本分支的原始 JSON、CSV 与报告为修正后的发布记录。不要继续引用修正前“纯暂停 C/D 分配约为 A 的两倍”作为内核结论。
