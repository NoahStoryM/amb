# 阶段 B/C：参考实现与验证结果

环境：Racket 9.3 CS。先检查环境，原临时安装已不存在，使用有界下载/安装重新准备。原始研究目录与 pkgs/ 未修改；本次没有运行性能 benchmark。

## 实现规模与抽象边界

kernel.rkt 共 146 行（包含空行和注释），只导出任务中的 11 个名字。核心控制定义是 make-amb、amb-fail、amb-pause；四个 merge 不调用它们。sequence 游标与供应阶段检查各有独立、简短的实现位置，amb 与 for/amb 仅为派生语法。

阶段标记使用 continuation mark。实现初期使用私有参数曾意外使后续继承初次消费时的其它参数；现已修正，并用“现有选择固定策略、未来选择读取消费时环境、其它参数不被额外冻结”三类测试保留这个区别。没有改掉预期来迁就实现。

暂停观察覆盖默认跳过、每个逻辑暂停一次回调、零/多返回值、不把回调结果送回搜索、观察阶段的越界效应与独立搜索。测试还运行了缺少 thunk 调用、过早求备选、缺少右单位律、以及 sequence 接回不构成上下文逆运算的反例。

## 结论的范围

上述是可执行方程与有限前缀测试，不是对任意 Racket continuation、共享状态、异常恢复或任意自定义 merge 的形式化证明。自定义 merge 的零元律是语义前提，无法由参数的 procedure? 形状检查证明。phase 检查只拦截 amb 自己的三个效应，不是任意 Racket 控制操作的隔离系统。

当前原型明确采用完全惰性、单遍、供应阶段诊断和可选 #:on-pause；正式 API 的三项待定事项仍见 DESIGN §7。没有添加未来功能或生产优化来掩盖这些决策。
